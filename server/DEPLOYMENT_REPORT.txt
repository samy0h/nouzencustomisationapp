  🔐 REQUIRED ENVIRONMENT VARIABLES
═══════════════════════════════════════════════════════════════

DATABASE_URL
├─ Description: PostgreSQL connection string
├─ Value: Use INTERNAL Database URL from Render PostgreSQL
└─ Format: postgresql://user:pass@hostname:5432/dbname?schema=public

CORS_ORIGIN
├─ Description: Allowed frontend origins (comma-separated)
├─ Example: https://nouzen-clothes.netlify.app,https://www.nouzen.com
└─ Important: Include protocol (https://), no trailing slashes

ADMIN_AUTH_SECRET
├─ Description: Secret key for admin authentication
├─ Security: MUST be changed from default in production
└─ Generate: Use strong random string (32+ characters)

ADMIN_SAMY_PASSWORD
├─ Description: Password for Samy admin account
└─ Security: Use strong password, change default

ADMIN_AKRAM_PASSWORD
├─ Description: Password for Akram admin account
└─ Security: Use strong password, change default

RESEND_API_KEY
├─ Description: API key for sending order notification emails
├─ Get From: https://resend.com/api-keys
└─ Format: re_xxxxxxxxxxxxx

ORDER_NOTIFICATION_EMAIL
├─ Description: Email address to receive order notifications
└─ Example: orders@yourdomain.com

RESEND_FROM_EMAIL (Optional)
├─ Description: Sender email for order notifications
├─ Default: Nouzen Orders <onboarding@resend.dev>
├─ Production: Use verified domain email
└─ Example: Nouzen Orders <noreply@yourdomain.com>

═══════════════════════════════════════════════════════════════
  ⚠️  CRITICAL: FILE UPLOAD STORAGE ISSUE
═══════════════════════════════════════════════════════════════

PROBLEM:
The application currently saves order files to the LOCAL filesystem:
├─ Location: /uploads/orders/{orderNumber}/
├─ Files: Mockup images, design files, customization JSON
└─ Implementation: server/src/utils/orderFiles.ts

⚠️  Render's filesystem is NOT persistent!
   Files will be DELETED on every:
   ├─ Deploy
   ├─ Service restart
   └─ Dyno cycling

IMPACT:
   ✗ Order mockups will be lost
   ✗ Customer designs will be lost
   ✗ Customization data will be lost

SOLUTIONS (Choose One Before Production Launch):

Option 1: AWS S3 (RECOMMENDED)
├─ Pros: Industry standard, reliable, scalable
├─ Cost: ~$0.023/GB/month storage
├─ Setup: Install @aws-sdk/client-s3
└─ Env: AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, AWS_S3_BUCKET

Option 2: Cloudinary
├─ Pros: Image-focused, built-in transformations
├─ Cost: Free tier available (25GB/month)
├─ Setup: Install cloudinary package
└─ Env: CLOUDINARY_URL

Option 3: Backblaze B2
├─ Pros: Cost-effective S3 alternative
├─ Cost: ~$0.005/GB/month storage
├─ Setup: Install @aws-sdk/client-s3 (B2 is S3-compatible)
└─ Env: B2_ACCESS_KEY_ID, B2_SECRET_ACCESS_KEY, B2_BUCKET

Option 4: Render Persistent Disks
├─ Pros: Simplest migration (no code changes)
├─ Cost: $1/GB/month (more expensive)
├─ Setup: Add disk in Render, mount at /uploads
└─ Limitation: Not multi-region, backup responsibility

CODE TO UPDATE:
└─ server/src/utils/orderFiles.ts

TEMPORARY WORKAROUND:
   The app WILL work, but uploaded files will be lost on redeploy.
   Acceptable for testing, NOT for production.

═══════════════════════════════════════════════════════════════
  🐛 TROUBLESHOOTING GUIDE
═══════════════════════════════════════════════════════════════

Build Fails:
Problem: TypeScript compilation errors
Solution:
├─ Verify root directory is set to "server"
├─ Check Node version (should be 20.x)
├─ Review build logs for specific errors
└─ Ensure package.json scripts are correct

Database Connection Fails:
Problem: Cannot connect to PostgreSQL
Solution:
├─ Use INTERNAL Database URL (not External)
├─ Verify DATABASE_URL format includes ?schema=public
├─ Check PostgreSQL service is running
├─ Ensure services are in same region
└─ Test connection with: npx prisma db pull

CORS Errors in Frontend:
Problem: "Access-Control-Allow-Origin" error
Solution:
├─ Add exact frontend URL to CORS_ORIGIN
├─ Include protocol: https://your-frontend.com
├─ Remove trailing slashes
├─ Use commas without spaces for multiple URLs
└─ Restart service after changing env vars

Health Check Fails:
Problem: Render shows service as unhealthy
Solution:
├─ Wait 2-3 minutes after deployment
├─ Check service logs for startup errors
├─ Verify health check path is /api/health
├─ Test manually: curl your-backend.onrender.com/api/health
└─ Ensure PORT is not hardcoded

Prisma Errors:
Problem: Prisma Client not found or outdated
Solution:
├─ Verify postinstall script exists in package.json
├─ Run: npx prisma generate
├─ Clear build cache and redeploy
└─ Check Prisma version compatibility

Migration Fails:
Problem: "npx prisma migrate deploy" fails
Solution:
├─ Verify DATABASE_URL is correct
├─ Check database permissions
├─ Review migration files for syntax errors
├─ Try: npx prisma migrate resolve --applied <migration>
└─ For fresh start: npx prisma db push (dev only!)

Email Notifications Not Sending:
Problem: Order emails not arriving
Solution:
├─ Verify RESEND_API_KEY is valid
├─ Check Resend dashboard for errors
├─ Verify sender domain is verified in Resend
├─ Check ORDER_NOTIFICATION_EMAIL is correct
├─ Review application logs for email errors
└─ Test Resend API key independently

Files Not Persisting:
Problem: Uploaded files disappear after deploy
Expected:
├─ This is NORMAL behavior on Render
├─ Local filesystem is ephemeral
└─ See "FILE UPLOAD STORAGE ISSUE" section above
